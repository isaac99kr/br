## 후속 구현 단계

개발 가이드([cursor_bible_reading_development_guide.md](../cursor_bible_reading_development_guide.md)) 1~8단계와 정렬합니다.

### 1단계 — 조사·설계 확인

- 저장소·프레임워크·기존 코드 재확인 (현재는 사실상 빈 프로젝트)
- CSV·본문 인코딩·일정 분포 재검증
- 본 기획 문서(`docs/`)를 구현 기준으로 확정

### 2단계 — 일정 데이터 연결

- `asset/schedule/bible_reading_schedule.csv`를 앱이 읽을 수 있게 배치
- 컬럼 정규화, 246일·중복/누락 검증
- 필요 시 빌드 시 JSON 변환 (CSV 원본 내용 변경 금지)

### 3단계 — localStorage 진행 기록

- [05-progress-storage.md](05-progress-storage.md) 스키마 구현
- 조회/변경/저장, JSON 오류 복구, 완료 수·`lastReadDay`

### 4단계 — 홈 화면

- 진행률, 이어 읽기, 빈 상태, 날짜 찾기 진입
- UI는 [04-ui-screens.md](04-ui-screens.md) + HTML/스크린샷 참고

### 5단계 — 날짜 찾기

- 구약/신약 · 주차별 카드 · 필터 · 상태 표기
- 날짜 클릭 → 읽기 화면

### 6단계 — 읽기 화면

- 범위·이전/다음·상태 전이
- 본문: `asset/bible/개역개정-text` 연결 (CP949 → UTF-8 정규화)
- 본문 연결 전에는 자동 완료 비활성

### 7단계 — 반응형·접근성

- 모바일/태블릿/데스크톱
- 키보드·포커스·상태 텍스트

### 8단계 — 테스트·문서화

- 가이드 필수 테스트 체크리스트 수행
- README: 로컬 실행·빌드·GitHub Pages 절차

### (배포) GitHub Pages

- React + Vite(또는 기존 도구) `base: '/br/'` 등 경로 설정
- 해시 라우팅 또는 SPA fallback
- Actions 워크플로 (저장소 설정에 맞춤)
- 비밀값 하드코딩 금지

대상 저장소(가이드): `https://github.com/isaac99kr/br.git`  
배포 URL 예: `https://isaac99kr.github.io/br/`

## 기술 스택 (후속 확정안)

| 항목 | 선택 |
|---|---|
| UI | React SPA |
| 라우팅 | React Router (해시 라우팅 우선 검토) |
| 데이터 | 정적 CSV/JSON + localStorage |
| 백엔드 | 없음 |
| 배포 | GitHub Pages |

의존성은 필요한 만큼만. 큰 UI 키트는 기본으로 쓰지 않습니다.

---

## 구현 시작 전 체크

구현을 시작할 때 다음을 확인합니다.

1. 사용자가 **코딩 진행을 요청**했는지
2. `docs/` 기획과 충돌하는 요구가 없는지
3. `asset/` 원본을 덮어쓰지 않을지
4. 커밋·푸시는 **명시적 요청이 있을 때만**
