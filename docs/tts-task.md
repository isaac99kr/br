# Mac mini에서 창세기 1장 MP3와 절별 시간 JSON 생성

## 작업 목표

현재 열려 있는 `br` 저장소에서 기존 성경 데이터와 Angelina 음성 설정을 재사용하여 다음 작업을 실제로 완료해줘.

1. Mac mini에 필요한 실행 환경을 구성한다.
2. 개역개정 창세기 1장 전체 31절의 음성을 생성한다.
3. 장별 MP3 하나와 절별 시간 JSON 하나를 만든다.
4. 재실행 가능한 스크립트와 한글 실행 안내를 작성한다.
5. 스크립트를 실제 실행하고 결과를 검증한다.

계획이나 코드 작성만으로 끝내지 말고, 이 샘플의 실제 생성까지 진행해줘.

이번 범위는 창세기 1장 한 장이다. 성경 전체 생성, 웹 플레이어 수정, 배포, Git 커밋·푸시는 하지 않는다.

## 1. 먼저 저장소와 환경 확인

- 저장소의 `AGENTS.md` 등 적용되는 작업 지침을 확인한다.
- `git status`를 확인하고 기존 사용자 변경을 보존한다.
- macOS 버전, CPU 아키텍처, Python, ffmpeg 설치 여부를 확인한다.
- Apple Silicon이라고 추정하지 말고 실제 환경을 확인한다.
- 기존 `tts/.venv`와 설치된 Supertonic 패키지가 있으면 재사용 가능 여부를 확인한다.
- 시스템 Python이나 전역 패키지를 변경하지 않고 가상환경을 사용한다.

이전에 확인한 파일은 아래와 같다. 현재 체크아웃에서 다시 확인한다.

| 용도 | 경로 |
|---|---|
| 현재 음성 설정 | `tts/config/voice-selection.json` |
| Angelina 음성 스타일 | `tts/voices/angelina.json` |
| 창세기 본문 | `public/data/bible/krv/창.json` |
| 본문 가공 유틸리티 | `tts/scripts/tts_text.py` |
| 기존 일차별 생성기 | `tts/scripts/generate_day.py` |
| 생성물 제외 규칙 | `.gitignore` |

성경 본문의 장·절 구조는 다음과 같은 형태다.

```json
{
  "abbr": "창",
  "chapters": {
    "1": {
      "1": "<천지 창조> 태초에 하나님이 천지를 창조하시니라"
    }
  }
}
```

프로젝트의 `krv`는 개역개정 데이터 식별자로 사용되고 있다.
일반적인 외부 약어 의미로 임의 변경하지 않는다.

## 2. 기존 설정 재사용

현재 파일을 읽어 아래 값을 확인하고, 실제 파일의 설정을 사용한다.

- 엔진: `supertonic3`
- 모델: `supertonic-3`
- 언어: `ko`
- 음성: Angelina
- 스타일: `tts/voices/angelina.json`
- 속도: `0.9`
- 합성 단계: `12`
- 장 안내 뒤 무음: `0.5초`
- 절 사이 무음: `0.12초`

설정 파일과 위 값이 다르면 차이를 보고하고 현재 설정 파일을 기준으로 처리한다.

`tts/config/voice-styles.json`은 이전 Qwen 실험용일 수 있으므로 현재 생성 설정과 혼동하지 않는다.

참조 WAV가 없어도 저장된 Angelina 스타일 JSON으로 합성할 수 있는지 확인한다.
참조 녹음이나 음성 복제를 새로 만들지 않는다.

## 3. 생성 방식

이번 샘플은 다음 방식으로 구현한다.

```text
장 안내 별도 합성
→ 설정된 무음 추가
→ 1절 합성
→ 절 사이 무음
→ 2절 합성
→ ...
→ 31절 합성
→ PCM/WAV 상태에서 연결
→ MP3 한 번 인코딩
```

요구사항:

- 장 안내는 `창세기 일장 말씀입니다.`로 생성한다.
- 본문은 저장소 JSON에서 자동으로 읽는다.
- 매번 본문을 붙여 넣게 하지 않는다.
- `<천지 창조>` 같은 단락 제목과 NUL 등 제어문자를 제거한다.
- 가능한 경우 기존 `tts_text.py`의 본문 정리 함수를 재사용한다.
- 절 번호는 낭독하지 않는다.
- 31절이 모두 존재하고 본문이 비어 있지 않은지 검증한다.
- 절마다 생성된 파형의 실제 샘플 수를 누적하여 시간을 계산한다.
- 글자 수 비율로 절별 시간을 추정하지 않는다.
- 절별 MP3를 단순 연결하지 않는다.
- 마지막 절 뒤에는 불필요한 추가 무음을 넣지 않는다.

절별 합성은 절 경계의 억양이 초기화될 수 있다.
이번 작업에서는 정확한 구간 경계 확보를 우선하고, 자연스러움은 사용자가 청취해 판단할 수 있게 한다.

시간은 각 절의 합성 음성 구간을 뜻한다.
음성 내부의 앞뒤 무음까지 제거한 실제 발화 시점이라고 표현하지 않는다.

## 4. 실행 환경 구성

Supertonic 3는 ONNX/CPU 실행을 우선한다.
CUDA나 MPS 사용을 전제로 구현하지 않는다.

필요한 패키지와 도구:

- 호환되는 Python
- Supertonic 3 지원 Python SDK
- numpy
- soundfile
- 모델 다운로드용 huggingface_hub
- ffmpeg 및 ffprobe

기존 환경이 정상 작동하면 불필요하게 업그레이드하지 않는다.
재현 가능한 의존성 파일 또는 설치 스크립트를 남긴다.

ffmpeg가 없으면 기존 Homebrew 설치 여부를 확인한다.
Homebrew가 있다면 ffmpeg 설치를 진행한다.
Homebrew 자체가 없고 시스템 수준 설치가 필요하면 필요한 명령과 이유를 설명한다.

기존 SDK의 자동 모델 다운로드가 실패하면 아래 보관 소스를 후보로 확인한다.
접근 가능 여부와 API 호환성을 확인한 뒤 사용한다.

- SDK 저장소:
  `https://github.com/supertone-oss-archive/supertonic-py.git`
- SDK 고정 커밋:
  `df0f9686dac7fbbde391b759e2ee5286a3737622`
- Hugging Face 모델:
  `supertone-oss-archive/supertonic-3`
- 모델 고정 리비전:
  `aafc6e32416a594460b32413efc49d7fe4ce6d46`

명시적으로 모델을 다운로드한 경우 SDK에는 로컬 모델 경로를 넘기고 자동 다운로드를 끈다.

모델은 `tts/models/` 등 Git 제외 경로에 저장한다.
모델 가중치나 생성 음성을 Git에 추가하지 않는다.

## 5. 구현할 파일

기존 일차별 생성기를 유지하고 별도 장별 생성기를 추가한다.

권장 파일:

```text
tts/scripts/generate_chapter.py
tts/scripts/run_genesis_1.sh
tts/requirements-chapter.txt
tts/README-mac-mini.md
```

기존 프로젝트 구조에 더 잘 맞는 방법이 있으면 조정하되 최종 실행 명령을 명확히 남긴다.

### 장별 생성기

아래와 같은 명령으로 실행할 수 있게 한다.

```bash
tts/.venv/bin/python tts/scripts/generate_chapter.py \
  --translation krv \
  --book 창 \
  --chapter 1
```

최소 옵션:

- `--translation`
- `--book`
- `--chapter`
- `--force`: 지정한 대상만 재생성
- `--threads`: CPU 스레드 제한
- 필요하면 `--output-dir`

저장소 루트를 파일 위치 기준으로 찾는다.
실행한 터미널의 현재 디렉터리에 의존하지 않는다.

### 간편 실행기

저장소 루트에서 아래 한 줄로 실행할 수 있게 한다.

```bash
bash tts/scripts/run_genesis_1.sh
```

이 실행기는 환경을 확인하고 창세기 1장을 생성·검증한다.
모든 성경을 생성하는 배치를 호출하지 않는다.

Mac mini를 다른 용도로도 사용할 수 있도록 CPU 스레드 수를 설정 가능하게 한다.
기본값은 실제 CPU 수를 고려해 보수적으로 잡고 설정 방법을 안내한다.
기존 배치처럼 두 번역본을 병렬 생성하지 않는다.

## 6. 저장 경로와 재개

권장 결과 구조:

```text
tts/work/chapters/krv/GEN/001/<생성조건해시>/
  창세기_001.mp3
  창세기_001.json
  generation-config.json
  validation.json
  parts/
    announce.wav
    verse-001.wav
    ...
    verse-031.wav
```

- 생성조건 해시는 본문, 스타일 파일 내용, 합성 설정, 모델 버전, 생성 로직 버전 등을 반영한다.
- 같은 조건으로 재실행하면 정상 저장된 중간 WAV를 재사용한다.
- 본문·음성·설정이 바뀌면 이전 중간 음성을 섞어 사용하지 않는다.
- 임시 파일에 저장한 뒤 원자적으로 교체해 중단된 파일을 완료 파일로 오인하지 않게 한다.
- 재사용하는 WAV는 샘플레이트, 샘플 수, 손상 여부를 확인한다.
- MP3와 JSON의 존재 여부만으로 완료 처리하지 않는다. 해시와 메타데이터도 확인한다.
- Ctrl+C 이후 같은 명령으로 재개할 수 있게 한다.
- 진행 상황과 실패한 절을 터미널에 출력한다.
- 최종 MP3는 우선 모노 96kbps로 인코딩한다.

## 7. 시간 JSON 형식

시간 필드는 밀리초 기준이며 파일 안에 단위를 명확히 기록한다.
샘플 위치를 함께 저장하여 반올림 오차를 피한다.

아래 값은 형식 예시이며 실제 측정값으로 채운다.

```json
{
  "schemaVersion": 1,
  "translationId": "krv",
  "translationName": "개역개정",
  "book": "GEN",
  "abbr": "창",
  "chapter": 1,
  "audio": "창세기_001.mp3",
  "audioSha256": "실제 MP3 해시",
  "engine": "supertonic-3",
  "speaker": "Angelina",
  "speed": 0.9,
  "totalSteps": 12,
  "sampleRate": 44100,
  "timeUnit": "ms",
  "durationMs": 0,
  "timingMethod": "verse-synthesis-sample-count",
  "announcement": {
    "text": "창세기 일장 말씀입니다.",
    "startMs": 0,
    "endMs": 0
  },
  "verses": [
    {
      "verse": 1,
      "startSample": 0,
      "endSample": 0,
      "startMs": 0,
      "endMs": 0
    }
  ]
}
```

추가로 모델 리비전, SDK 버전, 소스 Git 커밋, 스타일 해시, 생성조건 해시 등을 기록한다.
샘플레이트는 예시 값을 하드코딩하지 말고 모델의 실제 값을 사용한다.
로컬 작업 트리가 수정된 경우 Git 커밋만으로 입력이 고정됐다고 주장하지 않는다.

`endMs`는 해당 절 음성 구간의 끝이다.
절 사이에 추가한 무음은 해당 절의 음성 구간에 포함하지 않는다.
다음 절의 `startMs`까지 공백이 있어도 정상이다.

JSON은 특정 모아 읽기 목록에 종속되지 않아야 한다.
향후 같은 MP3와 JSON으로 `창1:1-10`, `창1:11-20` 등을 재생할 수 있어야 한다.

## 8. 실제 실행과 검증

스크립트 구현 후 실제로 창세기 1장을 생성한다.

자동 검증:

1. MP3와 JSON이 모두 존재한다.
2. MP3를 ffprobe로 읽고 전체 디코딩할 수 있다.
3. JSON의 audioSha256이 실제 MP3와 일치한다.
4. JSON에 1~31절이 중복·누락 없이 순서대로 존재한다.
5. 모든 절에서 `startSample < endSample`이다.
6. 이전 절 종료가 다음 절 시작보다 늦지 않다.
7. 마지막 절 종료가 전체 길이를 넘지 않는다.
8. 모든 파형이 유한한 값이며 비어 있지 않다.
9. 원본 PCM 길이와 MP3 디코딩 길이를 비교하고 차이를 기록한다.
10. 재실행했을 때 완료된 합성을 다시 하지 않는지 확인한다.

MP3의 인코더 지연·패딩·디코더 차이를 고려한다.
시간축 차이가 발견되면 원인을 조사하고 필요하면 보정한다.
단순히 디코딩 길이가 같다는 이유로 모든 브라우저에서 샘플 단위 정확도가 보장된다고 보고하지 않는다.

청취 확인을 위해 최종 MP3를 디코딩한 결과에서 다음 샘플을 만든다.

- 1절만
- 10절만
- 1~10절 구간

이를 `tts/work/` 아래에 저장하고 경로를 알려준다.
사용자가 경계에서 다른 절의 말소리가 섞이는지 확인할 수 있어야 한다.

자동 검증이 통과해도 발음, 누락·반복, 억양 품질까지 검증됐다고 표현하지 않는다.
직접 듣지 않았다면 청취 검증을 했다고 주장하지 않는다.
