# 03. 데이터 모델

## 1. 읽기 일정 (다중 스케줄)

원본: [`asset/schedule/`](../asset/schedule/)  
빌드: `npm run data` → `public/data/schedules.json` + `public/data/schedules/{id}.json`  
하위 호환: `public/data/schedule.json`은 기본 스케줄(`chrono-246`) 복사본 (TTS 스크립트용)

### 등록된 스케줄

| ID | 제목 | 일수 | 그룹 | CSV |
|---|---|---|---|---|
| `chrono-246` | 연대기순 246일 | 246 | `testament-week` | [`chrono-246.csv`](../asset/schedule/chrono-246.csv) |
| `yearly-365` | 1년 1독 | 365 | `month` | [`yearly-365.csv`](../asset/schedule/yearly-365.csv) |

새 스케줄: CSV 추가 → [`scripts/build-data.py`](../scripts/build-data.py)의 `SCHEDULES` 레지스트리에 항목 추가 → `npm run data`.

### 공통 / 선택 컬럼

| 컬럼 | 의미 | 사용 |
|---|---|---|
| `reading_day` | 일정 번호 (1…N) | 공통 |
| `reading_range` | 그날 읽을 범위 | 공통 |
| `weekday` | 요일 약어 | `chrono-246` |
| `testament` | 권역 | 공통(표시) |
| `week_no` | 권역 내 주차 | `chrono-246` |
| `month` / `month_day` | 달력 월·일 | `yearly-365` |

- 구분자: **세미콜론 (`;`)**, UTF-8
- 검증: 각 스케줄 `reading_day`가 `1…dayCount` 연속. 실패 시 빌드 오류

### 일정 레코드 (정규화 후)

```json
{
  "day": 1,
  "weekday": "월",
  "testament": "구약",
  "week": 1,
  "range": "창1-3장"
}
```

달력형 예시:

```json
{
  "day": 32,
  "month": 2,
  "monthDay": 1,
  "testament": "구약",
  "range": "레11-14장"
}
```

### `reading_range` 복잡 패턴 예시

본문 연결 시 파서가 대비해야 할 패턴입니다.

| day | reading_range | 특징 |
|---|---|---|
| 1 | `창1-3장` | 단일 권, 장 구간 |
| 20 | `민9:1-14, 민1-3장` | 절 구간 + 장 구간, 쉼표 연결 |
| 22 | `민7-8장, 민9:15-23, 민10장` | 혼합 |
| 56 | `삼상18-20장, 시59편` | 다권, 시편은 `편` |
| 57 | `시1-2편, 시4-6편, 시8-17편, 삼상21장, 시34·56편` | `·` 로 비연속 편 |
| 184 | `눅1:1-38, 마1:18-25, …` | 신약 병행 본문 다수 |
| 216 | `행8:1-13, 행8:26-40, 행8:14-25, 행9:32-11:18, 행9:1-31` | 같은 장·권 안에서도 스케줄 순서 유지 (병합·정렬 금지) |
| 243 | `요일1-5장, 요이1장, 요삼1장` | 짧은 서신 |

표시용 문자열은 CSV를 그대로 쓰고, 본문 추출은 후속 단계에서 파서로 처리합니다.
쉼표로 나뉜 구간은 **왼쪽부터 스케줄에 적힌 순서 그대로** 읽습니다. 장·절 숫자순으로 합치거나 재정렬하지 않습니다.

## 2. 성경 본문 (다중 번역)

앱은 **개역개정(`krv`)** 과 **표준새번역(`rnksv`)** 을 지원합니다.  
원본 포맷은 다르지만 `npm run data`(`scripts/build-data.py`)가 동일한 JSON 스키마로 정규화합니다.

### 런타임 레이아웃 (`public/data/`)

| 경로 | 역할 |
|---|---|
| `translations.json` | 번역 카탈로그 (`krv`, `rnksv`) |
| `books.json` | 공유 책 목록·CSV 약어 aliases |
| `bible/krv/{abbr}.json` | 개역개정 본문 |
| `bible/rnksv/{abbr}.json` | 표준새번역 본문 |

책 JSON 스키마:

```json
{
  "abbr": "창",
  "file": "원본파일명",
  "chapters": { "1": { "1": "본문…", "2": "…" } }
}
```

설정(`bibleReadingSettings:v1`)의 `translationId`로 로드 경로만 바뀌며, 읽기 UI는 동일합니다.

### 2.2 표준새번역 원본 (`rnksv`)

경로: [`asset/bible/표준새번역개정판.txt`](../asset/bible/표준새번역개정판.txt)

| 항목 | 내용 |
|---|---|
| 파일 | 단일 txt (~31k lines) |
| 헤더 | `F1,표준새번역개정,F1` |
| 책 마커 | `{NN} 0:0 {약어},{전체이름},{장수}` 예: `01 0:0 창,창세기,50` |
| 절 형식 | `{NN} {장}:{절} [소제목] 본문` 예: `01 1:1 <천지창조> …` |
| 인코딩 | UTF-8 (CRLF) |

빌드 정규화:

- 단락 기호 `○` 제거
- 각주 마커·괄호 주석 제거 (`a본문.(a …)` → `본문.`)
- `<소제목>`은 개역개정과 같이 유지
- 원본 약어 `라`(에스라)→`스`, `더`(에스더)→`에` 로 파일 약어 통일

### 본문 연결 정책

1. 일정에는 범위 문자열만 있고, 본문은 선택한 `translationId`의 JSON에서 로드한다.
2. 본문이 실제로 렌더링될 때만 스크롤 자동 완료를 켠다.
3. 원본 파일은 보존하고, 앱용으로는 UTF-8 JSON으로만 변환한다.
