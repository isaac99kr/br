# 09. 신규음성(MP3) 재생 기능 기획

> **상태:** 구현 전 기획. 이 문서는 코드·음원·배포 파일을 변경하지 않는다.  
> **대상 스케줄:** `chrono-246`의 **220~246일차**.  
> **기존 기능과의 관계:** 「음성듣기」는 브라우저 TTS를 계속 사용하고, 「신규음성」은 사전 생성 MP3를 재생한다.

## 1. 목표

읽기 화면 하단에 **신규음성** 진입 버튼을 추가한다. 지원 일차에서는 `tts/legacy-audio/`의 생성 MP3로 성경을 낭독하고, 기존 브라우저 TTS와 동일하게 재생·일시정지·정지·배속·현재 절 강조·해당 절 스크롤을 제공한다.

지원하지 않는 일차 또는 해당 번역본의 음원이 없을 때는 재생 패널을 열거나 브라우저 TTS로 대체하지 않고 토스트 **`신규음성은 준비 중입니다.`**만 표시한다.

## 2. 범위와 제외

| 구분 | 결정 |
|---|---|
| 지원 일차 | 220~246일차(양 끝 포함) |
| 번역본 | 현재 설정의 번역본을 따른다. 로컬 저장소에는 `krv`, `rnksv` 여성 음원이 모두 있다. |
| 음성 | `female` / Angelina 생성본만 사용한다. 별도 음성 선택 UI는 만들지 않는다. |
| 지원 밖 | 1~219일차 및 247일차 이후(향후 스케줄)는 준비 중 토스트만 표시한다. |
| 기존 「음성듣기」 | Web Speech API 기반 브라우저 TTS로 유지한다. 신규음성과 동시에 재생하지 않는다. |
| 포함하지 않음 | 절을 선택해 그 절부터 MP3 재생, 다운로드, 백그라운드 재생 보장, 새 진행 상태 규칙 |

`tts/legacy-audio/`는 `.gitignore` 대상인 로컬 작업 저장소다. 실제 웹 제공 시에는 검수 완료한 MP3와 매니페스트를 추적되는 배포용 정적 경로 `public/audio/`로 선별 복사하며, 원본 레거시 폴더를 브라우저에서 직접 참조하지 않는다. 본문 음원의 공개 배포는 [07-bible-tts-plan.md](07-bible-tts-plan.md)의 저작권·배포 승인 조건을 선행한다.

## 3. 하단 메뉴와 상태 흐름

첫 번째 하단 액션 줄에서 버튼 순서는 다음으로 한다. 작은 화면에서도 신규음성이 기존 버튼 사이에 묻히지 않도록 동등한 크기의 버튼으로 배치하며, 현재 4개 버튼 폭에 5개를 억지로 넣지 않고 반응형 줄바꿈을 허용한다.

```text
자동스크롤 | 음성듣기 | 신규음성 | 읽기 시작 | 완료 표시
```

- 「신규음성」은 「음성듣기」 바로 다음의 중앙 액션으로 둔다.
- 지원 일차에서 누르면 MP3 플레이어 패널을 열고 버튼을 활성 상태(`신규음성 ✓`)로 표시한다.
- 재생을 누르면 절 하이라이트·본문 중앙 스크롤·상하 크롬 숨김 규칙을 기존 「음성듣기」와 같게 적용한다.
- 일시정지/정지/재생 종료 시 크롬을 다시 보이고 강조 상태를 정리한다. 재생 종료만으로 읽기 완료 처리하지 않는다.
- 자동스크롤, 브라우저 TTS, 신규음성은 서로 배타적이다. 하나를 시작하면 나머지를 정지하고 해당 패널/상태를 닫는다.
- 「음성듣기」의 브라우저/한글 화자 미지원 토스트는 그대로 유지한다. 「신규음성」은 브라우저 TTS 지원 여부와 무관하게 동작한다.

## 4. MP3 재생 설계

1. 현재 일차·번역본·`female` 조합으로 배포 매니페스트에서 항목을 찾는다.
2. 항목이 없거나 일차가 범위 밖이면 `신규음성은 준비 중입니다.` 토스트를 띄운다.
3. 항목이 있으면 단일 HTML `<audio>`로 MP3를 재생한다. 재생·일시정지·정지·0.75/1/1.25/1.5/2배속 UI와 진행 표시는 기존 오디오 패널의 행동을 따른다.
4. `timeupdate` 시 매니페스트의 절별 cue(`verses[].startMs`)로 현재 절을 찾는다. 장 안내 cue는 장 제목을 강조하고, 절 cue는 해당 절을 강조·중앙 스크롤한다.
5. 음원 오류·매니페스트/파일 404는 `신규음성을 재생할 수 없습니다. 잠시 후 다시 시도해 주세요.` 토스트를 표시하고 재생 상태를 해제한다. 오류 시 브라우저 TTS로 자동 전환하지 않는다.

MP3의 cue와 화면 본문은 **동일한 스케줄 범위·동일한 순서**여야 한다. 따라서 단지 재생 시간이 있는지보다, 매니페스트의 `range`, 장 cue, 절 cue가 현재 `chrono-246`에서 로드한 본문과 일치하는지를 배포 전 검증한다.

## 5. 기존 음원과 재생성 판정

### 5.1 판정 기준

MP3 생성/배포 기준은 `5355cff` (`2026-10-10`, *Publish day 214–246 dual TTS audio and deploy pipeline fixes*) 시점의 `public/data/schedule.json`이다. 현재 스케줄은 `public/data/schedules/chrono-246.json`이다.

두 버전에서 각 일차의 실제 로드 구절 순서를 비교한다.

- `weekday`, 주차, 화면 표기 등 낭독 텍스트에 영향을 주지 않는 변경: **재생성하지 않음**
- 범위 문자열의 표기만 달라도 파서 결과의 구절 ID와 순서가 같음: **재생성하지 않음**
- 구절 추가·제거·교체 또는 구절 순서 변경: 해당 일차의 **두 번역본(`krv`, `rnksv`) MP3와 cue를 모두 재생성**

최종 구현에서는 문자열 비교만으로 결론 내리지 않는다. 기준 커밋과 현재 데이터를 각각 파싱하여 `(책 약어, 장, 절)`의 순서 배열을 비교하고, 차이가 난 일차만 생성 대상 목록으로 만든다.

### 5.2 이번 범위의 Git 이력 대조 결과

220~246일차 생성 기준과 현재 스케줄을 비교한 결과, 아래 **6일차**는 실제 낭독 구절이 달라져 재생성이 필요하다. 각 일차는 `krv`와 `rnksv`를 모두 다시 생성하므로 총 **12개 MP3 + 매니페스트 cue**가 대상이다.

## 6. 배포 전 검수 기준

- 지원 27일 × 2번역본의 매니페스트 항목과 MP3 파일이 모두 존재한다.
- 223, 224, 226, 229, 235, 236일차는 현재 범위와 일치하는 새 MP3/cue이며, 이전 파일을 재사용하지 않는다.
- 각 지원 일차에서 재생, 일시정지, 정지, 배속, 종료, 절 하이라이트, 자동 스크롤과의 상호 배타를 확인한다.
- `krv`와 `rnksv`를 각각 선택해 해당 번역 음원이 재생되는지 확인한다.
- 219일차와 지원 범위 밖 일차에서 신규음성 버튼은 토스트만 띄우고 기존 읽기·브라우저 TTS 상태를 바꾸지 않는지 확인한다.
- 음원/매니페스트 404와 재생 실패 시 사용자에게 오류 토스트가 보이고 UI가 재생 중 상태에 남지 않는지 확인한다.

## 7. 구현 순서(승인 후)

1. 기준 커밋과 현재 스케줄의 파싱 결과를 비교하는 재생성 대상 검증을 실행하고, 위 6일차 결과를 재확인한다.
2. 대상 6일차 × 2번역본만 재생성하고, 220~246 전체의 배포용 MP3/매니페스트를 구성한다.
3. 기존 브라우저 TTS와 분리된 MP3 플레이어 상태를 추가하고 하단 「신규음성」 버튼을 연결한다.
4. 모바일 레이아웃과 지원 밖/오류 토스트를 검증한 뒤, 권리·용량 승인 범위에서 정적 배포한다.
